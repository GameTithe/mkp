# 진행 규칙

- 현업자 AI에게 보낼 질문을 라운드당 5개 작성하라. 사용자가 전달하고 답변을 가져온다.
- 모든 기록은 프로젝트 루트의 `info/questions.md` 하나에 누적하라.
- 시작·재개 시 기존 기록과 과제 자료를 먼저 읽고 라운드 번호를 이어라.
- 질문을 먼저 저장한 뒤, 복사 가능한 블록으로 제시하고 답변을 기다려라.
- 답변이 오면 해당 라운드에 원문과 분석을 추가하고 상단 요약을 갱신하라.
- 답변 처리가 끝나면 누적 정보를 바탕으로 다음 질문 5개를 저장·제시하라.
- 일부 답변만 오면 즉시 기록하고 나머지를 기다려라. 사용자가 건너뛰라고 하면 미응답을 표시하고 진행하라.

# 질문 선정

- 질문을 선행 정보에 따라 분기하는 설계 트리로 관리하라.
- 지금 확보한 정보만으로 물을 수 있는 질문 중 중요한 5개를 골라라.
- 같은 라운드의 다른 답변에 의존하는 질문은 다음 라운드로 미뤄라.
- 문제·업무 흐름·실제 사례·입출력·제약·예외·성공 기준의 핵심 공백을 우선하라.
- 한 질문에는 하나의 확인 목적을 담아라. 
- 모호하거나 모순된 답변은 근거 질문 ID를 짚어 재질문하라.
- 파일·환경에서 확인할 사실은 직접 조사하라. 필요하면 하위 에이전트에 독립 조사를 맡겨라.
- 현업자 답변, 공식 과제 조건, 너의 해석, 사용자 결정 사항을 구분하라.
- 유효한 질문이 5개 미만이면 억지로 채우지 말고 남은 공백과 종료 여부를 사용자에게 확인하라.

# 파일 형식

상단의 상태·요약·질문 트리는 갱신하고, 하단의 라운드 기록은 보존하라.

```markdown
# 현업자 인터뷰

## 현재 상태와 누적 요약
- 과제 / 현재 라운드 / 답변 대기 여부
- 확인된 정보와 근거 질문 ID
- 미확인 사항 / 모순 / 사용자 결정 사항

## 질문 트리
- 주제 / 선행 근거 / 상태 / 다음 질문 후보

---

## Round 001
### 질문
- R001-Q1. ...
- R001-Q2. ...
- R001-Q3. ...
- R001-Q4. ...
- R001-Q5. ...

### 답변 원문
사용자가 전달한 내용을 그대로 기록한다.

### 분석
- 질문별 답변됨 / 부분 답변 / 미응답
- 새 정보 / 해석 / 추가 확인 사항
```

# 보존과 종료

- 기존 질문과 답변 원문을 삭제하거나 요약으로 대체하지 마라.
- 정정은 원문을 남기고 추가 기록하라. 요약에는 최신 내용을 반영하라.
- 핵심 문제·범위·제약·성공 기준이 충분히 파악되면 남은 불확실성을 제시하고 종료 확인을 받아라.
- 인터뷰 종료만으로 구현을 시작하지 마라.
