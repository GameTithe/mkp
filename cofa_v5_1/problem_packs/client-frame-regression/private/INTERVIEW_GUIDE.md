# 면담 평가자 전용 — 고정 문항 강요가 아닌 참고 정답

1. CPU/GPU 시간을 더하지 않은 이유는? → 본 문제의 관측 프레임 시간 계약은 max이며 합은 오답. 실제 엔진에서 CPU/GPU 중첩과 대기·프레젠트가 있으므로 이 로그만으로 전체 파이프라인 인과관계를 증명하지 못함. 제출 코드의 실제 함수와 대조한다.
2. p95가 20개/21개에서 무엇을 선택하는가? → nearest-rank ceil(.95*n); n20은 19번째, n21은 20번째. 보간 p95와 다를 수 있다. 제출 코드가 다른 정의면 불일치를 확인한다.
3. 임계값 근처 반올림은? → 판정 전에 반올림하면 1.9999ms 등이 잘못 회귀 처리. 둘 다 충족하는 AND와 포함 경계가 중요.
4. baseline=0 또는 표본 부족은? → 0 분모에서는 퍼센트 null, 절대 2ms 조건; 양쪽 0 stable. 부족은 우선 insufficient, 가능한 진단 통계 유지.
5. 중복 키를 언제 선점하는가? → 행 유효성 통과 후; 잘못된 최초 행이 후속 정상 행을 막으면 오답. 워밍업도 중복 검사 다음.
6. 필터가 데이터 검증보다 먼저라면? → 전체 meta/warnings가 바뀌는 문제가 생김. 집계 후 필터가 계약.
7. 보안은? → 로컬 처리·원본 불변·추가 필드 미출력·오류 메시지 정제. 테스트 몇 개만으로 외부 통신 부재나 모든 민감정보 유출 차단이 증명되는 것은 아님.
8. 병렬 역할과 통합 이유는? → 실제 delegation/merge/test 로그와 응시자 답변을 대조. 에이전트 수 자체로 가점 금지.
9. 기술 선택·규모 대응은? → 제출 구현의 시간/메모리 특성을 설명하는지 확인. 정답집의 구조를 외웠다고 이해로 인정하지 말 것.
10. 도구 한계는? → 합성 데이터 기준 계약 검사이며 게임 성능 프로파일러/회귀 원인 분석 엔진 아님. 표본 독립성, 시나리오 동일성, 잡음/반복 실험 문제 제기 가능.

질문은 제출 소스/대화/실패 결과에 연결하고 한 번에 하나씩. 위 모범 포인트를 면담 중 응시자에게 제공하지 않는다. 참조 설계를 따르지 않아도 요구사항을 만족하면 인정한다.
