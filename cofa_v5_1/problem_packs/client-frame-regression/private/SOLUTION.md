# 정답집 · 응시 전에 열지 마세요

## 정답의 의미
이 문서와 truth.json은 본 창작 문제의 확정 업무 조건입니다. private/reference/는 이를 만족하는 **하나의** 참조 구현입니다. 소스 구조가 동일해야 정답인 것은 아닙니다. 모든 필수 업무 조건은 공개 계약 또는 현업 담당자 질문으로 얻을 수 있습니다.

## 확정 명세
truth.json의 R01~R11이 기준이며, 담당자도 정확히 동일한 레코드를 사용합니다. 새로운 조건을 임의로 추가하지 않습니다.

## 기준 처리 파이프라인
입력 구조 검증 → 행 검증/정규화 → 첫 유효 키를 채택하는 중복 제거 → frame<3 워밍업 제외 → 시나리오/빌드 집계 → nearest-rank p95 → 표본 충분 여부 → 2ms AND 10% 회귀 경계/0 기준 특례 → candidate CPU/GPU p95 차이 기반 병목 라벨 → 정렬 → AND 필터 → 정해진 JSON 출력.

판정은 반올림 전 수치를 사용합니다. 표본이 모자라도 가능한 쪽의 진단 통계는 보여줍니다. 원본/추가 민감정보를 결과나 오류에 싣지 않습니다.

## 참조 구현과 테스트
`reference/app.py`는 CLI 경계, `reference/framescope.py`는 순수 집계/판정 함수입니다. Python 표준 라이브러리만 사용합니다. `reference/test_reference.py`는 참조 함수 자체 검사입니다.
최종 사례의 기대값은 cases JSON에 독립적으로 고정되어 있으며, 채점 시 참조 코드를 실행해 정답을 만들어 비교하지 않습니다.
`private/expected/sample_output.json`은 배포 샘플의 정답 출력입니다.

## 비유일 설계와 수용 조건
float 또는 Decimal, dict 또는 정렬 기반 그룹화, 절차형/객체지향, 다른 언어 + app.py 어댑터 모두 허용합니다. 입력 크기 n에 대해 정렬 방식은 O(n log n), 데이터 저장 O(n)인 단순 구현이면 120분 범위에서 합리적입니다. 외부 서비스·GUI는 필수 아님.
성능 측정 없이 초당 처리량이나 “실제 게임 병목 원인”을 단정하면 안 됩니다. 실제 엔진 타이밍·드라이버·측정 반복 실험은 이 데이터 도구 밖의 한계입니다.

## 수동 검토
RUNBOOK 내용의 진위, 자체 테스트 품질, 계층 분리/중복, 네트워크 송신·로그 출력 코드, 민감정보 취급, 제출자가 설계를 설명하는지 별도로 봅니다. 자동 테스트 통과만으로 3축 만점을 주지 않습니다.
