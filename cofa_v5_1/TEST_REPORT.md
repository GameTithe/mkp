## 세 가지 재현 문제의 수정 검증

**채점 실패와 피드백:** 면담 종료(completed) 직후 모델 없이 사실 피드백 생성. 최종 채점 호출 실패·재시작 후에도 실제 검사 결과와 면담 답변 유지. 타이머/시험 재시작 없이 재평가 가능. 제출본·로그 변조 또는 필수 검사 기록 누락은 정상 피드백이 아닌 경고로 차단합니다.

**품질 지표:** 최초 점수가 기대 범위에 있어도 원문 재검토 보류/오류이면 reviewed_match=false. raw_match는 진단용으로만 남기고, 정당한 관찰 불가와 기술적 실패를 구별합니다. 이 경로는 합성 provider로 실제 benchmark 실행기에 넣어 검사했습니다.

**원문 배분:** 5,100/3,800/1,500자 등 작은 합성 문맥에서 코드가 길어도 본인 면담/실행/의사결정 원문을 평가축별로 우선합니다. 정확한 substring/offset, 부분 제공 표시, 반대 근거 우선, 미제공 그룹 표시, 요약 초과 오류를 검사했습니다. 모든 문맥에서 모든 원문이 포함된다는 주장은 하지 않습니다.

## 추가 경계 검증

담당자 재검토는 원래 질문 시점의 대화와 공개 상태를 사용하며, 성공한 재검토는 질문당 1회입니다. 동일 질문 반복으로 정보가 쌓이지 않음, 실패 후 재시도, 정답 일괄 요청 제한, 제출 후 차단, 분류 변화가 환경 결함 확정으로 바뀌지 않음을 검사했습니다.

인접 점수 재검토는 원문으로 지지된 두 정수 중 하나 또는 null만 허용합니다. 큰 차이/관찰 여부 불일치/허위 인용/범위 밖 점수/호출 실패/환경 문제를 별도로 검사했습니다. 이 검사에서 나온 점수는 합성 입력에 대한 로직 결과이지 실제 응시자의 성적이 아닙니다.

## 실제 서버 검사와 UI 검사 구분

HTTP 도구는 개발→담당자/재검토→요구사항 확인→제출→실제 제출본 검사→예측 실행→면담 종료→사실 피드백→합성 평가 장애→피드백 보존→재평가→종료 코칭→정답 공개→변조 차단을 실행했습니다. 초기 미구현 스텁의 최종 검사 결과는 **0/48**, 역량 점수는 **null**입니다. 참조 구현의 48/48을 응시자 성과로 사용하지 않습니다.

Chromium 검사는 정적 실제 화면에 메모리 모의 API를 연결했습니다. 개발 중 피드백 차단, 재검토 버튼, 채점 전/실패 뒤 피드백, 코치 연결, 정답 공개 시점, 390px 배치를 검사했습니다. **사용자 브라우저→실제 HTTP→인증 Codex의 전체 경로를 실측한 것은 아닙니다.**

## 회귀 도중 발견한 호환 문제

첫 전체 검사에는 기존 ValueError를 RuntimeError로 바꾸어 API 예외 종류가 달라진 오류 1건이 있었습니다. 모델 응답/근거 ID 검증 실패의 ValueError는 보존하면서 사실 피드백을 생성하도록 수정했고, 그 이후 **전체 208개를 다시 실행하여 통과**했습니다. 기존 검사를 지우거나 skip으로 회피하지 않았습니다. 기존 담당자 사례 개수 검사만 의도된 12→24 확장에 맞게 갱신했습니다.

## 새 압축 해제 검증 및 배포 동등성

배포 후보 ZIP을 새 폴더에 풀어 변경 영역 **43개**, 참조 함수 **6개**, 실제 HTTP **21단계**, Chromium UI **7항목**, 문제팩/사례 형식/문법을 다시 통과했습니다. 새 폴더에서 전체 208개를 다시 실행한 것은 아닙니다. 검사한 실행 코드·설정·프롬프트·문제·테스트 파일의 SHA-256과 최종 배포본이 일치하는지 확인합니다. 이후 추가한 것은 결과 보고 문서입니다.

- 전체 회귀 원문: `docs/regression_v51/summary.json`, 각 shard txt/json.
- 새 폴더 검사: `docs/v51_release_check_results.json`, `v51_release_*.txt/json`.
- 참조 결과: `docs/v51_reference_final.json`.
- 배포 실행 파일 해시: `docs/v51_tested_execution_hashes.json`.
- v5 대비 변경 목록/업무 정답 불변: `docs/v51_change_summary.json`.

## 확인하지 못한 범위

실제 로그인된 Codex/원격 LLM이 없어 질문 이해·의미 재검토·면담·피드백 품질을 실측하지 못했습니다. Windows 실기기, 실제 150분 연속 운용, 전문가 점수 교정, 편향/인젝션의 완전 방지, OS 파일 격리도 검증하지 않았습니다. 기준 사례 36개는 출제자 작성 미교정 자료입니다. 별도 LLM 세션이나 반복 일치는 사람 평가의 독립성·정확성과 같지 않습니다.

```powershell

python tools/run_regression_shards.py --workers 4 --output ../regression_v51
python tools/v51_http_check.py --output ../http_v51.json

```

앞의 회귀/HTTP/형식 검사는 오프라인 DEMO/테스트 대역입니다. `doctor --live`는 실제 사용자 계정·네트워크·사용량이 필요하지만 시험 타이머는 시작하지 않습니다. 실제 모델 사례 검사는 `quality live --scope stakeholder --repeats 2`와 `--scope judge`로 따로 할 수 있으며 추가 사용량과 정답 노출에 주의하세요. UI 개발 검사는 Playwright/Chromium이 필요한 선택 도구이고 일반 시험 실행에는 설치하지 않아도 됩니다.
