# 인수인계

## 확인한 목표·조건과 근거

- `MISSION.md`: baseline/candidate 프레임 로그를 재현 가능하게 비교하고 확인 우선순위를 제공.
- `CONTRACT.md`: CLI/JSON 구조, 오류 코드, 필수 필드와 enum. 담당자 추가 응답은 없음.

## 구현한 범위 / 의도적으로 남긴 범위

- `app.py`: UTF-8(BOM) 입력, 안전한 오류 JSON, 행 검증, 워밍업/중복 처리, p95 집계, 판정/병목/정렬/필터.
- `tests/test_app.py`: 정상 샘플, 경계, 부족 표본, BOM, 중복/손상 행, CLI 오류 테스트.
- DB·네트워크·UI·외부 의존성은 근거가 없어 제외.

## 실행한 명령·실제 결과 / 아직 검증하지 않은 것

- `python -m unittest discover -s tests -v` → 5 tests, OK.
- 전체 샘플/전투 필터/빈 입력 명령 → 모두 종료코드 0, 상세 결과는 RUNBOOK.md.
- 미검증: `../exam.py check`, 별도 인수 검사, 대용량 처리량.

## 실패·수정·재검증 내역

- Windows stdout 기본 인코딩으로 CLI 테스트 실패 → UTF-8 고정 후 통과.
- 손상 JSON이 IO_ERROR로 분류됨 → 예외 순서 수정 후 INVALID_INPUT 테스트 통과.

## 선택한 구조의 이유 / 대안 / 실패 조건

- 단일 Python 모듈+표준 라이브러리가 계약을 충족하는 최소 구조. 업무 임계값은 담당자 미확인 가정이며 PLAN.md에 질문과 함께 분리.

## 다음 담당자의 첫 작업과 완료 조건

- PLAN.md의 7개 질문을 담당자에게 확인하고 상수/집계/정렬 테스트를 확정 기준으로 수정한 뒤 자체 테스트와 허용된 인수 검사를 재실행.
