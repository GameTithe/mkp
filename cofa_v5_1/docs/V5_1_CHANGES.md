# v5.1 변경 기록 — v5 안정화

검토 입력: `V5_REVIEW_INPUT.md`. 공식 COFA 내부 구현이나 배점으로 확인한 내용이 아니라 기존 모의환경 코드의 결함 수정과 연습 정책 개선입니다.

## 1. 채점 실패와 피드백 잠금을 분리
`engine.evaluate`에 시도/성공/실패 상태를 기록합니다. 시험 종료(completed)에서도 `feedback.load_inputs`가 모델 없이 사실 리포트를 구성합니다. 면담 종료 자동 생성, 채점 오류 후 자동 보존, CLI/화면 접근, 재시작 후 접근을 검사했습니다. 시험을 다시 시작하거나 타이머를 초기화하지 않고 evaluate를 재시도합니다.

무결성 실패/필수 기록 누락은 일반 모델 오류와 다릅니다. `feedback_blocked.json`과 경고 HTML만 표시하고 정상적인 검증 결과나 새 점수를 만들지 않습니다. 기존 성공 평가가 파일로 남아 있을 수 있으나 실패 중인 회차의 API는 그것을 현재 최종 결과로 제공하지 않습니다.

## 2. 품질 검사 지표 수정
`benchmarks.summarize_judge_attempts`에서 raw_match, reviewed_match, status를 분리했습니다. matches_authored_fixture는 reviewed_match의 호환 별칭입니다. 원문 재검토가 보류·오류이면 최초 점수가 기대와 같아도 통과로 집계하지 않습니다. 정당한 관찰 불가는 expected_unobserved, 기술적 실패로 생긴 null은 error/review_hold로 구분합니다.

범위별 live 검사(`--scope stakeholder|judge|all`)와 담당자 반복 검사를 제공합니다. 전체 결과의 상태별 건수를 남깁니다. 기준 사례 기대 범위와의 일치 및 반복 안정성은 사람 평가 정확성과 다릅니다. 사례별 채점 반복은 각 초안과 원문 검토를 검사하며 전체 150분 시험을 재현하는 것은 아닙니다.

## 3. 최종 원문 문맥 배분 수정
기술은 실행·코드, 의도는 본인 지시·업무 대화, 인지는 본인 답변·코드·실행의 공간을 먼저 예약합니다. 부정/불확실 관찰의 근거도 고려합니다. 최종 채점/면담/피드백 모두 사용하며 전체 관찰 요약은 버리지 않습니다.
긴 원문은 정확한 부분문자열과 excerpt_start/end/full_content_characters/excerpt_partial로 표시합니다. raw_selection은 역할별 제공/미제공, 부분 원문, 반대 근거의 미제공을 기록합니다. 충분한 공간이 없으면 누락을 드러내며, 요약 자체가 한도를 넘으면 오류로 중단합니다. 완전한 이해/의미 정확성을 보장하는 선택 알고리즘은 아닙니다. 각 항목 원문 재검토에는 선택 ID의 전체 원문을 다시 제공합니다.

## 4. 담당자 질문 재검토
`contextual.reconsider`, `ask-review`, 화면 버튼. 기존 질문 이벤트 ID와 당시 대화/공개 상태로 한 번 재해석합니다. 원래 답변을 덮어쓰지 않고, 내부에 최초/재검토 분류를 모두 남깁니다. 분류 변화는 환경 결함 확정이나 자동 가감점이 아닙니다. 공개량을 늘리지 않으며 같은 질문을 반복해 새 답을 캐내는 기능으로 쓰지 못하게 성공 1회로 제한합니다. 실패하면 재시도할 수 있습니다. 개발 단계에서만 작동합니다.

담당자 기준 사례를 12개에서 24개로 늘렸습니다. 동치 표현·짧은 후속 질문·틀린 가정·요약/일괄 요청을 포함합니다. 실제 모델 호출 품질은 이 제작 환경에서 측정하지 않았습니다.

## 5. 보류 사유와 좁은 점수 경계 검토
근거 부족, 관찰 여부 불일치, 인접 점수 경계, 큰 점수 차이, 반대 근거, 환경 문제, 재검토 오류, 문맥 초과를 구분합니다. 원문 검토로 지지된 인접 두 점수만 추가 검토할 수 있습니다. 원문·앵커에 따라 두 정수 중 하나를 선택하거나 null로 보류하며 평균은 만들지 않습니다. 허위 인용/범위 밖 점수/호출 실패는 확정하지 않습니다. config의 adjudicate_score_boundaries로 이 추가 호출을 끌 수 있습니다.

총점을 미확정으로 둔 상태에서도 나머지 확정 항목은 보고합니다. 불완전한 항목을 새 분모로 환산해 완성된 총점처럼 만들지 않습니다. 추가 LLM 검토를 사람 교정/독립 평가자로 표현하지 않습니다.

## 유지되는 계약
개발 120분·본인 면담 30분, 3축9기준, 모의 배점, 문제팩 교체, 기록·병렬 구현·검증·정답 공개 기능을 유지합니다. FrameScope 업무 정답과 48개 인수 기대값은 수정하지 않았습니다. 문제팩 버전만 담당자 품질 사례 확장을 표시하는 2.0.1입니다.
