# 기록 범위·보안·제약

## 무엇을 저장하는가

관리형 브라우저/CLI의 사용자 입력, AI 응답, 역할별 프롬프트, Codex 공개 JSONL 이벤트, stderr, 마지막 응답, 직접 명령 stdout/stderr/종료 코드, 파일 변경 해시, 편집기 저장 내용, 위임/병합, 면담 질문/답변을 저장합니다.
JSONL에 제공된 tool output 자체가 Codex 내부에서 이미 축약되어 있다면 그 이전의 전체 프로세스 내부 출력을 복원하지 못합니다. `exam.py run`으로 직접 실행한 명령의 출력은 따로 전체 수집합니다.
다른 앱이나 별도 Codex 세션의 대화, 화면/키보드 전체, 모델의 비공개 내부 추론은 수집하지 않습니다. 외부 터미널에서 수동으로 실행한 명령도 자동 수집하지 않습니다.

## 원문 보존과 평가 입력

원문은 로컬 로그에 저장합니다. 일반 비밀키 패턴은 평가용 근거 생성 시 일부 마스킹하며, `.env`, 인증 파일, 개인키 파일, `.git`, 의존성/캐시 디렉터리는 제출/평가 대상 복사에서 제외하고 목록을 남깁니다. 임의의 모든 비밀을 탐지하는 보장된 필터가 아닙니다.
개인정보/회사 코드/실계정 데이터를 넣지 마세요. 로그를 외부에 공유하기 전에 확인하세요. 원문 로그는 자동으로 인터넷에 업로드되지 않지만, LLM 모드의 질문·코드·평가용 근거는 Codex 호출에 전달되므로 계정에 설정된 모델 제공자가 처리합니다.

## 접근 제어 수준

웹 서버는 127.0.0.1만 바인딩하며 시작 때마다 생성한 토큰, Host/Origin 확인을 사용합니다. 토큰 포함 주소를 공유하거나 포트포워딩하지 마세요.
작업 디렉터리는 별도 복사본이고 Codex에는 read-only/workspace-write 샌드박스 옵션을 전달하지만, 역할 프롬프트는 OS 수준 보안 경계가 아닙니다. 로컬 사용자가 private/나 로그 DB를 읽고 변경하는 것을 막는 시험 감독 시스템은 아닙니다.
강한 격리가 필요하면 전용 VM/OS 계정으로 실행하고 개인 파일/자격증명을 분리해야 합니다. 이 패키지는 그 구성을 자동 설치하지 않습니다.

직접 실행하는 응시자 테스트는 자신의 컴퓨터에서 실행하는 프로그램입니다. 명령 환경에서 일부 토큰 환경변수를 제거하지만 로컬 디스크 접근·네트워크·악성 코드 실행을 모두 차단하지 않습니다. 출처를 모르는 코드는 검토 없이 실행하지 마세요.

## 평가의 한계

해시 체인은 우발적 손상/변경 탐지를 위한 것입니다. 모든 파일을 가진 로컬 소유자가 DB와 해시까지 재작성하는 공격을 막지 못합니다.
프롬프트 인젝션 저항 지침, 근거 ID 검사, 구조화 출력 검증을 적용하지만 평가자의 의미적 오판/모델 편향을 제거하지 못합니다.
기준별 confidence는 모델이 보고한 수치이며 교정된 정답 확률이 아닙니다.
웹 UI의 개발 시간/면담 차단은 앱 수준 제약입니다. OS 편집기에서 직접 수정하는 것을 금지하지 못하며, 제출본만 이후 평가 대상으로 고정합니다.


## v4 문제팩과 담당자 정보 분리
`public/`만 응시자 workspace로 복사합니다. 담당자 호출에는 업무 truth 전체와 대화 기록만 넣고 참조 코드·비공개 기대값·면담 정답은 넣지 않습니다. LLM은 사실 ID만 선택하고 서버가 검증된 업무 문장을 출력합니다. 브리프에 없는 조건은 확정 사실로 승인하지 않습니다.
이 분리는 **프롬프트와 애플리케이션의 논리적 분리**입니다. 같은 사용자 권한의 파일시스템 접근을 막는 격리는 아닙니다. 코딩 에이전트가 상위 폴더를 읽는 행위를 프롬프트로 금지하지만 OS 수준 강제 차단은 하지 않습니다.
`problem_packs/*/private`, `logs/calls`, `analysis`에는 출제 의도와 내부 명세가 들어 있습니다. 처음 연습할 때 직접 읽지 마세요. 최종 평가가 끝난 후 정답 공개 명령을 사용합니다. 사전 유출 여부를 완벽히 검사하는 부정행위 방지 제품은 아닙니다.
문제팩의 검사 명령과 참조 구현은 로컬 프로그램을 실행합니다. 모르는 출처의 문제팩을 자동 신뢰하지 마세요. validate는 구조 검사일 뿐 악성 코드 안전성 인증이 아닙니다.


## v5 공개 범위
종료 피드백과 코칭 API는 evaluated 단계·면담 종료·제출 검사 존재·해시 무결성을 확인합니다. 일부 인수 사례가 실패해도 피드백은 열립니다. 평가/피드백 원문은 종료 후 정답에 관한 내용을 포함할 수 있습니다. requirements 내부 판정에는 사실 ID가 있지만 후보 화면에는 본인 문장과 결과만 제공합니다.

예측 실행은 고정 제출본의 복사본을 사용하고, 출제된 입력·runner만 연결합니다. 로컬 임의 Python 실행을 OS 수준으로 격리하는 기능은 여전히 없습니다. 제출 코드를 신뢰할 수 없는 제3자에게서 받았다면 별도 OS/컨테이너 격리가 필요합니다.

정확한 인용 검사와 점수 재검토에도 모델의 의미 오류·프롬프트 인젝션 가능성은 남습니다. 품질 검사 사례는 강제 보안 증명이 아니며, LLM 코치 자유 답변은 원문 인용 자동 검사를 거친 평가 결과와 구분해야 합니다.
