## 기본 구성 (v4 기능 유지)

| 구성 | 내용 |
|---|---|
| 문제 1개 | **FrameScope: 클라이언트 성능 회귀 분석** — 두 빌드의 프레임 로그를 비교하는 로컬 분석 도구 |

| 자동 기록 | 확인한 조건을 대화 로그 및 `REQUIREMENTS_CONFIRMED.md`에 기록. 주 에이전트와 병렬 작업에 전달 |
| 교체 연결 | 문제 선택 한 번으로 업무 브리프·초기 파일·테스트·평가 참고·면담 기준을 함께 교체 |
| 실행 검증 | 공개 스모크 4개, 최종 인수 사례 48개. 최종 48개에는 공개 4개가 포함됨 |
| 평가 연동 | 제출본 실제 실행 결과 + 작업 기록 + 문제 명세 + 30분 본인 답변을 3축 평가에 전달 |
| 정답 공개 | 최종 평가 후 `problem debrief`로 전체 해설/참조 구현/기대값 내보내기 |

이 과제는 게임 클라이언트 **개발 지원 도구** 과제입니다. 실제 client 시험이 반드시 같은 유형이라는 뜻은 아닙니다. 게임 엔진/그래픽스 구현 과제를 그대로 복원한 것도 아닙니다.

시작한 회차의 문제 ID/버전/파일 해시는 고정됩니다. 문제팩이 변경되면 담당자·제출·면담·평가를 중단합니다.

## AI 담당자의 정보와 동작

담당자는 **업무 정답 전체**를 제공받습니다. 참조 구현, 테스트 입력·기대값, 채점용 면담 해설은 입력 프롬프트에 넣지 않습니다.

```text
사용자 질문 + 담당자 대화 이력 + 확정 업무 조항
                    ↓
           Codex LLM의 구조화된 선택
                    ↓
      실제 존재하는 조항 ID인지 서버 검증
                    ↓
        선택된 업무 조항의 확정 원문으로 응답
                    ↓
       대화 로그 + 확인한 요구사항 문서 갱신
```

질문에 관련된 조건은 직접 답합니다. p95 정의나 업무 임계값처럼 구현에 필요한 **업무 규칙**은 숨기지 않습니다.
일반적인 첫 질문에는 업무 개요를 답합니다. **전체 명세를 한 번에 요구해도 개요만 알려줍니다.** 구체적인 업무 질문에는 관련 조항을 알려주되 신규 조항은 한 답변에 최대 3개입니다. 이는 공식 수치가 아니라 변경 가능한 연습 설정입니다. 이미 확인한 조항은 다시 설명하고, 요약 요청에는 확인한 내용만 모읍니다. 특정한 비밀 질문이나 전문용어를 맞혀야 하는 방식은 아니며, 개별 조항의 예외를 따로 숨기지 않습니다.

코드 정답·비공개 테스트·내부 프롬프트 요청은 거절합니다. 브리프 밖의 사실은 미확정이라고 답합니다. 이미 확정된 조건을 변경하는 제안은 승인하지 않습니다.

**LLM은 질문을 이해하고 조항을 선택하며, 수치가 들어 있는 업무 답변은 정답 명세 원문으로 고정합니다.** 문장 생성의 자유보다 일관성을 우선한 모의환경 설계입니다. 자유로운 협상/새 요구 추가를 하는 일반 챗봇은 아닙니다. 질문 해석 자체는 잘못될 수 있으므로 엉뚱한 조항을 받으면 재질문하세요. DEMO의 질문 해석은 키워드 기반이며 실제 LLM과 다릅니다.

각 조항은 `[R05]` 같은 ID로 답변에 표시됩니다. 이 ID를 PLAN, 테스트, 설명 근거에 연결할 수 있습니다. 공개한 조건 개수나 질문 수만으로 가점을 주지 않습니다.

## 실행

Python 3.10 이상, Node.js/npm, 설치·로그인된 Codex CLI가 필요합니다. Python 외부 의존성은 없습니다.

```powershell
npm install -g @openai/codex
codex login
python exam.py doctor --live
python exam.py serve --open
```

모델명은 config.json에서 null이면 사용자 Codex 설정을 따릅니다. 실제 모델 호출은 계정 사용량/요금/동시 실행 제한을 따릅니다. 설치·인증은 사용자 PC에서 수행합니다.

브라우저 대신 CLI:

```powershell
python exam.py start --mode llm
python exam.py ask "이 도구의 사용자와 성공 조건은 무엇인가요?"
python exam.py chat
python exam.py agent parallel --tasks tasks.json
python exam.py merge 작업ID
python exam.py check
python exam.py audit
python exam.py submit
python exam.py qa start
python exam.py qa answer "내가 선택한 구조와 검증 근거..."
python exam.py qa finish
python exam.py evaluate
python exam.py problem debrief
```

`chat`은 여러 줄 입력 후 `:send`, 종료는 `:quit`. 직접 실행은 `python exam.py run -- python ...`로 기록합니다.
`qa retry`는 생성 실패한 후속 질문을 재시도하며, 이미 보낸 답변을 보존하고 타이머를 초기화하지 않습니다.

## 검증과 평가의 구분

`exam.py check`는 개발 중 **공개 연결 검사**와 응시자 자체 테스트를 실행합니다. 자체 `test*.py`가 없으면 미설정으로 기록합니다. 초기 스텁은 공개 검사부터 실패하는 것이 정상입니다.

제출 후 면담 준비 시 고정 제출본의 별도 복사본을 대상으로 **최종 인수 48개**를 실행합니다. 기대값은 출제 시 고정된 JSON이며, 채점 중 참조 코드를 호출해 생성하지 않습니다. 상세 사례 결과는 내부 근거로 보존하고 최종 리포트에 포함합니다.

자동 검사는 입출력 동작에 대한 근거입니다. GUI/엔진 통합/전체 보안/코드 유지보수성/본인의 이해를 자동으로 인증하지 않습니다. R11 납품·재현 및 코드 품질은 수동/LLM 검토 항목도 있습니다.

기술·의도·인지 3축/9개 기준은 사용자 제공 이미지에 기반합니다. 하위 0~4, 축별 /100, 세 축 동등 가중치는 **모의 배점**입니다. 실행 검사 통과율을 역량 총점으로 자동 치환하지 않습니다. 정답집 또는 사용량 수치만 인용해서 수행 점수를 주지 못하게 검증하며, 인지에는 응시자 본인의 면담 답변 근거가 필요합니다.

관리 대상 전체 기록은 여러 조각으로 분석합니다. 최종 채점은 전체 관찰 요약과 문맥 예산 내 원문을 사용합니다. 로그의 모든 원문을 한 번에 모델에 넣는다는 뜻은 아닙니다. 실제 LLM 판단의 타당도와 재현성을 보장하지 않습니다.


## v4.1 변경 사항

**YouTube 원본 자막/음성을 확보해 전사한 버전이 아닙니다.** 진행자의 동일 인터뷰 공개 문답 정리에서 확인 가능한 내용과 공식 Cofa 설명을 근거로 조정했습니다. 원문 페이지 일부는 직접 열 때 목록으로 이동하여 검색 색인에 공개된 본문을 확인했습니다. 원영상 전체 내용/정확한 발언 시각과의 대조는 하지 못했습니다. 출처·조회 범위는 [PODCAST_SOURCE_NOTES](docs/PODCAST_SOURCE_NOTES.md)에 있습니다.

- 담당자: 단계적 공개를 서버에서 적용합니다. 명세 전체 요청과 이미 확인한 조건의 요약을 구분합니다.
- 판단 기록: 목표·제약·범위·검증·실패·자원·재사용 등의 메모를 남길 수 있습니다. 항목별 메모 수 자체는 점수가 아닙니다.
- 평가 지침: 단순한 질문의 유용성, 근거 있는 범위 조절, 위임의 검증 책임, AI 제안의 선택/기각을 봅니다. 불필요한 기능과 필수 안전 조치를 구분합니다.
- 사용량: `python exam.py usage`, 화면의 사용량 펼침 영역, 최종 `reports/resources.json`에 실제 보고된 토큰·호출 상태·시간을 표시합니다. 개발과 환경 운영을 분리하고 금액은 추정하지 않습니다.
- 사전 자료: `prep import`로 텍스트 지침만 반입하며 출처·목적·해시를 남깁니다. 자동 설치/실행은 하지 않습니다. 실제 시험의 반입 허용을 뜻하지 않습니다.
- 면담: 일반론 대신 제출 코드/기록/본인 답변에 맞춰 선택 이유·실패 조건·수정 검증·재사용의 적합성을 묻도록 지침을 보강했습니다.

타이머는 요청한 **120분 + 30분**, 문제는 같은 FrameScope(문제팩 1.1.0)입니다. 공식 가중치/합격선/모델을 추정하여 추가하지 않았습니다.

## 사전 지침과 사용량

문제 선택을 먼저 마친 뒤, 시험 시작 전에 실행합니다. 허용하는 것은 UTF-8 `.md/.txt/.json/.yaml/.yml` 지침 파일이며, 실행 파일은 복사하지 않습니다.

```powershell
python exam.py prep import "C:\my-codex-kit" --label my-kit --origin "본인 작성" --purpose "검증 지침 재사용"
python exam.py prep list
python exam.py usage
```

`workspace/prepared/`의 출처 문서와 해시는 시험 시작에 고정합니다. 이미 있던 자료를 새로 만든 성과로 간주하지 않으며, 실제로 검토하고 적용한 근거가 있어야 합니다. 반입은 하네스 전체 실행이나 Codex 스킬 자동 등록이 아닙니다. 파일 검사도 완전한 보안 검사가 아니므로 비밀키/회사자료를 포함하지 마세요.

사용량은 현재 회차의 관리된 Codex 이벤트에 대해서만 집계합니다. `cached_input_tokens`는 입력 토큰의 부분집합이라 총계에 다시 더하지 않습니다. 미보고는 0이 아닌 미측정입니다. 병렬 호출 시간 합은 실제 경과 시간이 아닙니다. 낮은 사용량만으로 고득점을 주지 않으며, 응시자 작업과 무관한 담당자/제출 후 자동 검토/면담/채점 토큰은 환경 운영으로 분리합니다. 실시간 값과 최종 값은 이후 호출만큼 달라질 수 있습니다.

## 보안과 기록 범위

브라우저/기록형 CLI를 거친 질문·답변·공개 Codex 이벤트·명령 출력·편집·위임·병합·면담을 기록합니다. 다른 앱/외부 Codex/비공개 내부 추론까지 수집하지 않습니다.
원문 프롬프트에는 업무 정답이 포함될 수 있어 내부 로그를 응시 도중 열지 않아야 합니다. 실제 개인정보·회사 코드·API 비밀을 입력하지 마세요. Codex에 전달되는 정보는 모델 제공자가 처리합니다.

역할·폴더·화면 공개 범위 분리는 **OS 수준 보안 격리나 부정행위 방지**가 아닙니다. 로컬 파일의 소유자는 private/와 로그를 열 수 있습니다. 강한 격리에는 별도 계정/VM/컨테이너와 파일 접근 설계가 필요하며 이 패키지는 자동 구축하지 않습니다. 제3자 문제팩의 검사 명령은 로컬 코드를 실행하므로 출처를 검토하세요.

브라우저 서버는 loopback+토큰 인증을 사용합니다. 서버를 닫으면 자동 마감은 멈춥니다. 시작/면담 시각은 저장되어 재실행으로 리셋되지 않습니다. 동결 제출본만 면담/평가에 사용하며 파일 변조를 검사합니다.

v3 호환 로직과 기존 회귀 검사는 보존되어 있지만, 기본 선택된 v4 문제팩에서는 과거 CSV 과제/14개 검사를 사용하지 않습니다. 기존 진행 중인 v3/v4 세션을 v4.1로 자동 이전하지 않습니다. 새 폴더에서 시작하세요.
