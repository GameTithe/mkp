## 이번 버전의 핵심

| 영역 | 구현 |
|---|---|
| 현업 담당자 | 업무 상황/현재 흐름/불편/우선순위를 설명하는 맥락형 답변. 구체적인 규칙을 질문하면 정확한 명세를 답함. 전체 요구사항·풀이 일괄 공개는 제한 |
| 요구사항 확인 | 응시자가 작성한 문장을 확인·정정·미확정으로 구분. 정답 조항 ID와 자동 완성 요구사항 문서는 기본 실전 모드에서 숨김 |
| 근거 연결 | 문장 ID Q001에 계획·구현·검증 이벤트를 직접 연결. 자기신고이며 자동 가점 아님 |
| 평가 재검토 | 같은 기록을 평가축별 두 번 채점. 별도 LLM 세션에서 실제 원문 인용·반대 근거·환경 요인을 검토. 지원 부족·환경 오류·호출 오류·점수 불일치를 구분. 인접 점수는 원문 재검토 후 하나를 확정하거나 보류 |
| 실행 예측 면담 | 먼저 본인 코드의 출력을 예측하고, 고정 제출본을 실제 실행한 결과를 비교 설명. 참조 정답 실행이나 자동 수정이 아님 |
| 종료 피드백 | 제출 검사와 면담이 끝나면 LLM 없이 사실 기록 생성. 채점 실패에도 접근 가능. 평가가 완료된 뒤 근거 있는 강점·개선·다음 연습 추가 |
| 복습 코치 | 시험 이후 질문 가능. 채점 미완료 상태에는 사실 확인/재시도 안내만 제공하며, 능력 해석은 평가 완료 후. 코치 대화는 점수에 섞이지 않음 |
| 품질 검사 도구 | 채점 기준 사례 12개 + 동봉 문제 담당자 질문 24개. 형식 검사와 실제 계정 반복 실행을 구분. **사람 기준과 교정되지 않은 출제자 작성 사례** |

기존 120/30분 타이머, 기록형 Codex 채팅, 최대 4개 별도 작업 복사본, 명시적 충돌 검사 병합, 독립 Auditor, 제출본 복사/해시, 모든 평가 대상 로그의 청크 분석, 3축/9기준, 텍스트 지침 반입, 사용량 분리, 문제팩 교체는 유지합니다.

## v5.1 안정화 포인트

- 시험 완료(completed)와 채점 성공(evaluated)을 분리합니다. 면담이 끝나면 `feedback`은 실제 검사·제출·면담 기록을 표시합니다. 최종 채점이 실패하면 `evaluate`는 오류를 반환하고, session.assessment에 실패·시도 횟수를 남기며 피드백을 보존합니다.
- `quality live`의 최초 점수(raw_match)와 원문 재검토 이후 결과(reviewed_match)를 분리합니다. 오류나 보류를 검증된 통과로 집계하지 않습니다. 사람 교정이 된 수치는 아닙니다.
- 원문 발췌는 기술/의도/인지별 기록 유형에 먼저 공간을 배분합니다. 긴 코드 때문에 본인 답변이 밀려나는 것을 줄이고, 부분 인용은 정확한 원문의 offset·길이·누락 종류를 공개합니다. 요약은 임의로 버리지 않습니다.
- 담당자 탭의 `담당자 질문 재검토`는 원래 질문과 당시 문맥을 새로 검토합니다. 질문당 성공 1회이고 최초 답변을 지우지 않습니다. 분류 변화 자체는 담당자 오류 확정이 아닙니다.
- 점수 보류 사유는 근거 부족/관찰 불일치/점수 경계/큰 점수 차이/반대 근거/환경 문제/검토 오류/문맥 한도로 구분합니다. 하나가 미확정이어도 나머지 확정 항목과 피드백을 그대로 표시합니다. 불완전한 총점을 새 분모로 환산하지 않습니다.

`python exam.py ask-review` 또는 `python exam.py ask-review E00000012`로 재검토할 수 있습니다. 개발 시간은 멈추지 않으며 실제 호출에는 계정 사용량이 발생합니다.

## 실행

Python 3.10 이상 + 설치·로그인된 Codex CLI가 필요합니다. Python 외부 패키지는 없습니다. Node.js/npm은 Codex 설치에 필요합니다.

```powershell
# 기존 설치/로그인이 있으면 처음 두 줄은 생략
npm install -g @openai/codex
codex login
python exam.py doctor --live
python exam.py serve --open
```

`doctor --live`는 계정 연결을 확인하며 타이머를 시작하지 않습니다. 화면에서 실제 LLM 모드를 선택한 후 시작하세요. 서버 터미널을 닫으면 자동 마감이 작동하지 않습니다. 코딩은 화면의 **Codex CLI 열기**로 띄운 실제 Codex TUI를 사용하며, 그 대화·도구 실행·파일 변경은 사이트 기록과 평가에 연동됩니다.

VS Code에서는 이 폴더를 연 뒤 Python 인터프리터를 선택하고, `F5` → **COFA: 웹 콘솔 실행**을 선택하면 됩니다.

**DEMO는 연결 점검용입니다.** 현업 응답은 키워드 분기, 요구사항 확인은 항상 미확정, 코딩은 하지 않으며 실제 점수/강점·약점은 만들지 않습니다.

## 실제 연습 흐름

1. 담당자에게 업무 상황과 필요한 조건을 질문합니다. 담당자 응답이 최종 요구사항 문서로 자동 정리되지는 않습니다.
2. 자신 또는 개발 AI가 정리한 이해를 `요구사항 확인` 탭에 한 줄 한 문장으로 제출합니다. 담당자는 해당 문장만 확인·정정하며 묻지 않은 전체 조건을 보충하지 않습니다.
3. Plan/Env/Agents/Handoff, 실제 구현/테스트/판단 기록을 갱신합니다. Q001에 실제 E... 이벤트를 연결할 수 있습니다.
4. 구현 제출 후 제출본 검사를 수행하고 30분 면담을 시작합니다. 첫 질문 준비가 끝나면 면담 타이머가 시작합니다. 후속 LLM/실행 대기는 면담 시간에 포함됩니다.
5. 면담을 마치면 우선 사실 피드백이 생성됩니다. 능력 평가를 위해 `최종 평가 + 피드백`을 누릅니다. 모든 검사가 **통과**해야 피드백을 받는 것은 아닙니다. 검사의 실행 결과와 실패도 피드백 대상입니다.
6. `종료 피드백 보기`에서 결과를 읽고 `복습 코치`에서 질문합니다. 평가 항목이 보류되어도 확정된 항목과 개선 피드백을 확인할 수 있습니다. 채점 자체가 실패했으면 `최종 평가 + 피드백`으로 재시도합니다. 점수 생성 후 피드백 호출만 실패했다면 `피드백 재생성`으로 재시도합니다.

## 담당자는 어디까지 답하는가

업무 명세 전체를 보고 질문의 의도를 구조화해 분류하는 LLM과, 허용된 정보를 결정하는 서버를 분리했습니다. 일반 업무 질문은 출제자가 작성한 상황 설명을 사용하고, 구체 질문은 정확한 업무 규칙을 사용합니다. 사실의 수치를 LLM이 새로 만들지 않습니다. 특정 비밀 단어나 반드시 거쳐야 할 질문 순서는 없습니다. 직접 핵심을 짚으면 바로 답합니다.

전체 풀이·체크리스트 대필 요청은 업무 개요로 제한하고, 신규 정확한 조항은 응답당 최대 3개입니다. 이 숫자/분류 방식은 공식 COFA 규칙이 아니라 연습 설정입니다. 이미 들은 내용을 요약할 때 새 조건을 누설하지 않습니다. 질문 분류와 문장 확인의 의미적 판단에는 LLM 오류가 남습니다.

`workspace/REQUIREMENTS_REVIEW.md`에는 **본인이 제시한 문장**과 확인 결과만 쌓입니다. 확인된 한 문장이 그 요구 조항 전체의 이해·구현·검증을 뜻하지 않습니다. 담당자의 원문 대화는 개발 AI에게 계속 전달됩니다.

## 종료 피드백 파일

```text
reports/final_report.html       점수·반복 점수·원문 근거 재검토
reports/exam_facts.json         채점 전/실패 시 검사·면담 사실 기록
reports/feedback.html           종료 피드백과 인용 원문
reports/feedback_blocked.json   무결성/필수 기록 오류 시 경고 (정상 결과 아님)
reports/feedback.md             텍스트 피드백
reports/feedback.json           기계 판독 결과
reports/resources.json          개발/환경 운영 사용량
reports/debrief/               평가 이후 별도 공개하는 정답·해설
```

피드백은 요구사항의 공개/본인 문장 확인/자기신고 근거 연결/실제 인수 테스트 결과를 구분합니다. 보류는 0점이 아닙니다. 인용 문구 존재 검사는 인용을 의미적으로 잘 해석했다는 보장이 아닙니다. 복습 코치의 자유 답변은 추가 조언이며 새 실행 검증이나 공식 재채점이 아닙니다.

python exam.py start --mode llm --model MODEL_NAME

python exam.py quality validate

`quality live`는 담당자 분류와 채점·재검토 경로를 실제 모델로 반복 검사합니다. 기준 사례와의 일치율은 사람 평가 정확도가 아닙니다. 기준 자체가 사람 교정 전 자료임을 리포트에 표시합니다. 케이스 결과에는 정답 관련 정보가 있을 수 있으므로 실전 시작 전 응시자가 결과를 읽지 않는 편이 좋습니다.

## 문제팩 교체

동봉 문제: FrameScope — 클라이언트 성능 회귀 분석, **문제팩 2.0.1**. 업무 정답과 48개 사례 기대값은 v5와 동일합니다. 이번에는 담당자 동치 질문·짧은 후속 질문·잘못된 전제·과다 공개 검사 사례를 확장했습니다. 엔진/그래픽스 시험의 실제 출제 유형을 확인한 문제는 아닙니다.

```powershell
python exam.py problem list
python exam.py problem validate
python exam.py problem new-session client-frame-regression "../practice_02"
# 다른 문제
python exam.py problem new another-problem --title "새 문제"
```

`problem.json`이 공개 자료·정답·테스트·담당자·면담을 연결합니다. [출제 계약](docs/PROBLEM_PACK_AUTHORING.md)과 [v5 확장 규격](docs/V5_PROBLEM_EXTENSIONS.md)을 참고하세요. 새 문제는 자동 완성되지 않으며 출제자가 정답과 기대값을 작성·검증해야 합니다.

## 비용·성능·보류

기본 설정은 3개 평가축 × 2회 채점, 점수가 있는 하위 항목에 대해 최대 9회 근거 재검토, 종료 피드백 1회입니다. 원문 재검토에서 지지된 인접 점수 차이는 해당 항목에 한해 추가 호출이 생길 수 있습니다 (adjudicate_score_boundaries=true). 평균이나 낙관적 점수를 자동 선택하지 않습니다. 여기에 전체 로그 청크 분석·면담·개발 호출이 추가됩니다. 로그가 길수록 계정 사용량/지연이 늘어날 수 있습니다. 반복 채점은 병렬 개발 에이전트 수와 별개이며 사람 독립 평가자와 같지 않습니다.

근거 재검토 원문이 문맥 한도를 넘으면 해당 항목을 보류합니다. 모델 실패·잘못된 인용·반복 불일치의 원인을 구분해 남깁니다. 이 보류는 응시자의 0점이나 능력 부족으로 치환되지 않습니다. 자동 점수의 전문가 타당도/재현성/공정성이 인증된 시스템이 아닙니다.

## 안전과 검증 한계

이 도구는 로컬 훈련 도구이지 OS 보안 샌드박스가 아닙니다. 본인과 로컬 실행 코드는 `private/`를 읽을 수 있습니다. 실제 개인정보·회사 코드·인증키를 넣지 마세요. 내부 호출 로그에는 업무 정답이 담길 수 있습니다. 신뢰할 수 있는 문제팩만 사용하세요.

실제 로그인 Codex·Windows 실기기·실제 150분 연속 운용·사람 교정된 채점 품질은 여기서 검증하지 못했습니다. 자동 테스트와 프로토콜 테스트 대역은 모델의 의미 판단 품질을 대신 증명하지 않습니다. 정확한 실행 결과는 TEST_REPORT.md를 읽으세요.

v4.1/v5 진행 중 회차에 덮어쓰지 말고 **새 폴더에서 새 회차**를 시작하세요. 기본 v5.1 실전 모드와 별개로 기존 회귀 호환 코드/레거시 담당자 모드는 유지했습니다.
